# v1.3.0-tandem.1 validation

`v1.3.0-tandem.1` was measured on the repository test suite and a clean macOS ARM64 installation. With Go 1.26.5, 168 tests/subtests passed, CLI statement coverage was 82.9%, golangci-lint 2.12.2 reported 0 issues, and govulncheck 1.6.0 reported 0 vulnerabilities. The release tag points to commit `747b5d191ce727b6e5d932a72ed5c10fad69a583`.

Automatic browser-cookie discovery changed from `browserutils/kooky` → no browser-cookie package in the compiled dependency graph. `gh image extract-token` → removed. `gh image auth-store` requires an interactive terminal, reads with echo disabled, rejects `--token`, and stores the GitHub session under the dedicated `tandemhealth-gh-image` OS credential. The upload protocol and one-PNG evidence restrictions are unchanged. A live upload was not run because this validation did not provision or read a developer session credential.

Clean pinned installation:

```console
$ gh extension remove image
$ gh extension install tandemhealth/gh-image --pin v1.3.0-tandem.1
$ gh extension list
gh image  tandemhealth/gh-image  v1.3.0-tandem.1
$ gh image --version
gh-image v1.3.0-tandem.1
```

The installed release refused non-interactive credential provisioning and rejected a relative screenshot before repository or credential access:

```console
$ gh image auth-store </dev/null
Error: reading session token: auth-store requires an interactive terminal

$ GH_IMAGE_EVIDENCE_ROOT=/tmp gh image relative.png --repo tandemhealth/gh-image
Error validating screenshot: PNG path must be absolute: "relative.png"
```
